# 管线细则与 abridged.json

## abridged.json

放在简读版目录根，`build-reader.py` 和 `qa-abridged.py` 都读它。

```jsonc
{
  "slug": "western-philosophy-stumpf",   // localStorage 命名空间，必须全局唯一
  "bookTitle": "西方哲学史（斯通普夫/菲泽第9版）",  // 笔记 front matter 用
  "shortTitle": "西方哲学史",             // 侧栏大标题
  "bookMeta": "斯通普夫 / 菲泽 · 第9版",   // 侧栏副行
  "edition": "第9版",
  "versionLabel": "v2.0 · 原书简读版",
  "output": "western-philosophy-stumpf-v2.0-原书简读版.html",
  "notesFilename": "西方哲学史-v2.0-读书笔记.md",
  "backupFilename": "西方哲学史-v2.0-标注备份.json",

  // ↓ 阶段 1 从原书读出来的结构，随书而变，脚本不写死
  "narrative": "按时代正序推进；每章内部是问题—理论—人物",
  "chapterSections": ["本章定位", "关键问题", "理论应对", "代表人物", "本章小结", "主要问题"],
  "guideSections": ["时代定位与时间线", "本时代关键问题", "理论应对的接续",
                    "代表人物索引", "逐章阅读", "时代总结", "留给下一时代的问题"],
  "kindLabels": { "chapter": "逐章正文", "guide": "时代导航" },

  // ↓ 可选，缺省即用下表默认值
  "qaLimits": {
    "guideBytes": [6000, 11000],
    "bookendBytes": [6000, 25000],
    "chapterMinBytes": 8000,
    "chapterMaxBytes": 60000,
    "groupTitleChars": 12
  },

  "groups": [
    { "name": "导读",        "guides": ["00-导读与目录.md"] },
    { "name": "古希腊",      "guides": ["10-古希腊哲学.md"],           "chapters": [1, 2, 3, 4] },
    { "name": "希腊化与中世纪", "guides": ["20-希腊化与中世纪哲学.md"],  "chapters": [5, 6, 7, 8] },
    { "name": "文艺复兴与近代", "guides": ["30-文艺复兴与近代哲学.md"],  "chapters": [9, 10, 11, 12, 13] },
    { "name": "十九世纪",     "guides": ["40-十九世纪哲学.md"],         "chapters": [14, 15, 16] },
    { "name": "二十世纪与晚近", "guides": ["50-二十世纪与晚近哲学.md"],  "chapters": [17, 18, 19, 20] },
    { "name": "总结",        "guides": ["60-全书总结与主要问题.md"] }
  ]
}
```

`groups` 的顺序就是阅读顺序，也是读书笔记里章节分组的顺序。
`chapters` 里的数字对应 `章节/NN-*.md` 的编号前缀。

`chapterSections` 是 `qa-abridged.py` 的校验依据，缺了会直接报错退出——
这是为了逼出阶段 1，不让人拿上一本书的骨架接着用。
`kindLabels` 决定阅读器里每篇正文顶部的小标签；不填时导航页显示"分组导航"。
分组不叫"时代"的书（部、篇、阶段、主题），把 `guideSections` 和 `kindLabels` 一起换掉。

## qaLimits

| 字段 | 默认 | 卡什么 |
|------|------|--------|
| `guideBytes` | 6000–11000 | 分组导航页膨胀成第二份正文，或空到没导航价值 |
| `bookendBytes` | 6000–25000 | 导读与全书总结要收全书，天然比导航长，单独给区间 |
| `chapterMinBytes` | 8000 | 章被压成提纲（简读版最常见的失败形态） |
| `chapterMaxBytes` | 60000 | 压缩没发生，等于抄了一遍 |
| `groupTitleChars` | 12 | 脑图卡片里的分组标题折行 |

字数差异大的书（短章随笔、超长专著）先按实际分布调这几个值，
不要为了让 QA 变绿去改内容。

```
├── 20-…  30-…  40-…  50-…

├── 章节/
│   ├── 01-苏格拉底的前辈.md
│   └── …  20-晚近的哲学.md
├── 片段/                     ← 可选，编译时追加到同名篇末尾

└── <output>.html
```

## 并行任务的写法

**按源文字数切批，不按篇数切。** 一个任务的源文控制在 1 万汉字上下、最多 2 篇。
章节长度差距大的书（毛选单篇从 130 字到 4.2 万字）尤其不能按篇数均分。

把**共用的编写规范写成文件**放在简读版目录下（例如 `编写规范.md`），
任务提示只留三样：读规范、读哪个文件、写哪个文件。提示越短，任务越不容易跑飞。

任务描述里必须出现：

1. 「先完整读 `<规范文件绝对路径>`」
2. 读哪个绝对路径、写哪个绝对路径（文件名必须与源文件一致）
3. 源文汉字数与目标汉字数（给出具体数字，不要只说"压一半"）
4. 长篇要额外点名「原文分了哪几章，每章都要覆盖到」，并要求回报覆盖了哪几章
5. 要求回报文件名、原文汉字数、简读稿汉字数、保留比例

**两个已经踩过的反例：**

- 让一个任务"读 162 万字节原文，按第 1—4 章整理成一个时代文件"——范围过大，
  不报错、不写文件，纯空转
- 让一个任务一次做 5 篇（合计 2.5 万汉字）并把完整规范写在提示里——
  跑了 8 分半，一个文件都没落盘

范围一大就静默失败，这是这条流水线最贵的坑。宁可多开任务。

## 版本号

| 版本 | 内容 |
|------|------|
| v1.x | book-learn-distill 的产出：原文、精读、图谱、Skill |
| v2.0 | 原书简读版：逐章简读稿 + 阅读器 |
| v2.x | 简读版的修订（补章、改结构、换阅读器能力） |

同一本书可以有多个简读版本并存，各占一个目录。

## 字数与阅读时间

`build-reader.py` 按汉字数统计，230 字/分钟折算精读时长写进侧栏。
西方哲学史 v2.0：16.9 万汉字，标注为约 12 小时精读；
实际快速通读 8–10 小时，边读边做批注 20–30 小时。
